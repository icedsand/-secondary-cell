# 유닛 이름 일괄 변경 rule

대상 : `rules/BatchRename.iLogicVb`

같은 유닛을 새 프로젝트로 다시 낼 때, 이름의 한 칸(프로젝트 코드)만 바꿔서
파일이름과 부품번호를 한 번에 정리한다.

```
LIKG-LM2102-FTL01-01.ipt  ->  LIKG-LM2601-FTL01-01.ipt
LIKG-LM2401-FTL06-01.iam  ->  LIKG-LM2601-FTL06-01.iam
          ~~~~~~                        ~~~~~~
```

최상위 조립도 하나에서 한 번 돌리면 트리 전체와 도면까지 처리된다.

## 원래 하던 방식과 무엇이 다른가

| | 원래 | 이 규칙 |
|---|---|---|
| 이름 입력 | BOM 에서 파일 수만큼 타이핑 | 조각 체크 + 새 값 한 번 |
| 부품 선택 | 조립도에서 골라 선택 | 없음 (트리 전체) |
| 서브조립도 | 하나씩 들어가서 다시 실행 | 필요 없음 |
| 도면 | 이름이 맞는 것만 | 참조까지 따라가 전부 |
| 결과물 | 사본이 새 폴더에 생김 | 제자리에서 이름이 바뀜 |

## 이름을 "칸" 으로 다룬다

한 유닛 안에 여러 해의 부품이 섞여 있다. 찾을 문자열을 손으로 넣는 방식이면
`LM2401`, `LM2301` 같은 것을 놓치고, 놓친 파일은 "안 바뀐 파일" 목록에 들어가
구매품처럼 보인다. 이름 규칙의 모양도 일정하지 않아 정규식으로 자동 탐지할 수
없다.

그래서 반대로 간다. 파일이름을 구분자로 쪼개 **칸별로 실제 등장하는 값을 전부
세어 보여준다.**

```
[1] LIKG      (247)
[2] LM2102    (229)    <- 이 칸이 프로젝트 코드다
[2] LM2401    ( 12)
[2] LM2301    (  6)    <- 하나라도 있으면 여기 뜬다
[3] FTL01     ( 19)
```

규칙 모양을 몰라도 되고, 무엇이 섞여 있는지 미리 알 필요도 없다. 여러 개를
체크하고 새 값 하나를 넣으면 전부 그 값으로 모인다.

**부분 일치 사고가 없다.** 칸이 통째로 같을 때만 바꾸기 때문이다.

```
칸 단위 : LIKG-LM2102-FTL01-01  ->  LIKG-LM2102-FTL01-99
단순치환: LIKG-LM2102-FTL01-01  ->  LIKG-LM2102-FTL99-99   <- 이렇게 되면 안 된다
```

### 목록을 짧게 두는 두 가지

- **구분자 개수** — `MIN_SEPS`(2) 개 미만인 이름은 대상에서 뺀다.
  `LIKG-LM2102-FTL01-03` 은 3 개, 구매품 `SHF-16` 은 1 개다.
  502 개 규모에서 조각이 87 → 40 개로 준다.
- **한글 조각** — 이름 규칙은 영문과 숫자뿐이라 한글이 있으면 코드가 아니라
  설명이다. 목록에만 안 넣고, 그 파일 자체는 다른 칸으로 정상 변경된다.

조각이 많으면 검색창으로 좁힌다. **검색을 바꿔도 체크는 풀리지 않으므로**
검색어를 바꿔가며 여러 칸을 고른 뒤 한 번에 규칙을 만들 수 있다.

## 핵심은 SaveAs 의 두 번째 인자다

```vb
SaveAs(경로, True)    ' 사본 저장. 열려있는 문서는 옛 파일에 그대로 남는다
SaveAs(경로, False)   ' 문서 자신이 새 파일로 옮겨간다
```

`False` 로 두면 인벤터가 **열려있는 모든 상위 문서의 참조를 자동으로 갱신한다.**
그래서 참조를 손수 이어붙이는 코드가 통째로 필요없다.

```
1) 최상위 조립도를 연다             - 트리 전체가 메모리에 올라온다
2) 관련 도면을 전부 연다 (비표시)    - 도면도 부품을 참조한 상태가 된다
3) 트리 아래쪽(부품)부터 SaveAs(새이름, False)
4) 도면도 SaveAs(새이름, False)
5) 전부 저장
6) 옛 파일을 _OLD 폴더로 옮긴다
```

**2번의 순서가 중요하다.** 도면을 이름 바꾸기 전에 열어야 한다. 뒤에 열면
도면이 옛 파일을 찾다 실패한다.

**이름부터 바꾸고 성공한 것만 부품번호를 손댄다.** 거꾸로 하면 이름 변경이
실패했을 때 부품번호만 옛 파일에 남아, 파일이름과 부품번호가 어긋난다.

서브조립도는 `AllReferencedDocuments` 가 돌려주는 평평한 목록의 한 항목일
뿐이라 부품과 똑같이 다룬다. 깊이가 몇 단이든 상관없다.

## 도면 짝짓기

1. 이름 규칙에 걸리고 **트리에 같은 이름의 부품이 있으면** 그것으로 끝.
   대부분 여기서 정해지고, 참조를 훑지 않아 빠르다.
2. 규칙에 안 걸려도 같은 이름의 부품이 있으면 그 부품을 따라간다.
3. 둘 다 아니면 열어서 참조를 본다. 이름이 어긋난 도면은 여기서 잡혀 그린
   부품의 이름에 맞춰진다.
4. 참조에도 이 조립도의 부품이 없으면
   - 이름 규칙엔 맞았다면 `[미사용]` 으로 두고 체크를 끈다
   - 그것도 아니면 상관없는 도면이므로 도로 닫는다

**버리는 모든 경우에 이유를 남긴다.** 그리고 한 줄 요약을 미리보기와 로그에
넣는다.

```
도면 : 발견 132 / 이름규칙 128 / 같은이름부품 0 / 참조 3
       / 관련없음 0 / 미사용 1 / 읽기전용 0 / 열기실패 0  ->  처리 대상 131 개
```

도면이 0 개로 끝나면 이 줄만 보면 어디서 빠졌는지 안다.

## 미리보기 표시

| 표시 | 뜻 | 체크 |
|---|---|---|
| `[!]` | 막힘 — 켜면 실행이 막힌다 | 꺼짐 |
| `[구버전]` | 새 이름이 겹치는데 더 최신인 코드가 있다 | 꺼짐 |
| `[미사용]` | 이 조립도에서 쓰지 않는 도면이다 | 꺼짐 |
| `[주의]` | 폴더는 다르지만 같은 이름이 생긴다 | **켜짐** |

### 겹치면 최신이 이긴다

```
LIKG-LM2401-FTL01-09.idw  ->  LIKG-LM2601-FTL01-09.idw   (바뀐다)
LIKG-LM2102-FTL01-09.idw  ->  [구버전] 그대로 둔다
```

프로젝트 코드에서 숫자만 뽑아 견준다. `LM2401` → 2401, `LM2102` → 2102.
큰 쪽이 최신이다. 숫자가 없거나 같아서 **가릴 수 없으면 임의로 고르지 않고
양쪽 다 막는다.** 잘못된 번호가 발주로 나가는 것보다 사람이 보는 편이 낫다.

## 구매품은 저절로 걸러진다

구매품 이름에는 우리 프로젝트 코드 칸이 없다. 바뀔 칸이 하나도 없으면 건드리지
않으므로, 컨텐츠센터와 라이브러리 부품도 같은 이유로 빠진다.

미리보기 아래쪽 "바뀌지 않는 파일" 목록에 빠진 이유가 하나씩 적힌다. 거기
가공품이 섞여 있으면 바꿔야 할 조각을 빠뜨린 것이다.

## 안전장치

- **이름이 겹치면 `_2` 를 붙이지 않는다.** 잘못된 번호가 발주로 나간다.
- **옛 파일은 지우지 않고 `_OLD_yyMMdd_HHmm` 폴더로 옮긴다.** 되돌릴 유일한 수단.
- 읽기전용 파일은 건드리지 않는다.
- 상관없는 문서가 열려 있으면 경고한다. 그쪽 참조까지 끌려가기 때문이다.
- 실행 전 미리보기에서 항목별로 뺄 수 있다.
- 기록을 `이름변경_yyMMdd_HHmm.log.txt` 로 남긴다. 실패는 로그 맨 위로 올린다.

## Inventor 2026 컴파일 위험을 피한 곳

**컴파일 오류는 `Try` 로 막을 수 없어서** 처음부터 이름을 적지 않는 쪽을 택했다.

- **`System.Drawing.Font` 를 직접 적지 않는다** (`SetMonoFont`).
  `Font` 속성의 `PropertyType` 으로 타입을 얻어 리플렉션으로 만든다.
- **`frm.AcceptButton` 대입을 리플렉션으로 넘긴다** (`SetDefaultButtons`).
- **`AscW` 대신 `Convert.ToInt32`** — `Microsoft.VisualBasic` 참조를 피한다.
- **람다와 `AddressOf` 델리게이트를 쓰지 않는다.** 정렬은 정렬 기준을 문자열에
  넣어 `List.Sort()` 로, 버튼 갈래는 `DialogResult` 로 처리한다. 저장소의 다른
  규칙에 전례가 없는 구문을 늘리지 않기 위해서다.

## 실제로 겪고 고친 것

| 증상 | 원인 |
|---|---|
| 부품번호는 바뀌는데 파일이름은 그대로 | 부품번호를 먼저 바꿔서, `SaveAs` 실패 뒤 "수정된 문서 전부 저장" 이 옛 파일에 썼다 |
| 도면만 통째로 안 바뀜 | 이름이 규칙에 맞아도 참조 짝을 못 찾으면 버렸고, 버리면서 로그도 안 남겼다 |
| 실행해도 아무 일이 없음 | 충돌로 체크가 다 꺼진 상태에서 조용히 종료했다 |
| 엉뚱한 도면이 충돌을 일으킴 | 조립도에 없는 부품의 옛 도면까지 끌어들였다 |

## 검증

- **정적** : 구조(Sub/Function/Class/Try/For/Do/If 짝), 문자열 따옴표,
  프로시저 선언·호출 인자 개수, 미사용 정의 — 통과.
  줄바꿈(`_`)을 이어붙인 뒤 검사한다.
- **로직** : 502 개 규모로 칸 수집·정렬·치환, 검색 중 체크 유지, 도면 짝짓기,
  최신 우선 충돌 해소, 판 번호 비교를 시뮬레이션으로 확인.
- **실사용** : 264 개 부품/조립도 이름 변경 확인. 도면 처리는 v9 에서 동작 확인.
- COM 호출 전반은 인벤터가 있는 환경에서만 확인할 수 있다.

## 남은 것

- **폴더 이름은 바꾸지 않는다.** 파일 이름과 부품번호만 바꾼다.
- 구분자는 `SEP` 상수로 `-` 하나다. 구분자가 섞인 이름 규칙은 지원하지 않는다.
- **Vault 로 옮긴 뒤에는** Copy Design 이 이 작업을 정식으로 지원한다.
  번호매기기 규칙으로 일괄 치환이 되고, 어느 조립도가 그 부품을 쓰는지도 Vault
  가 추적한다. 서버에서 개인 작업공간으로 통째로 복사해 오는 단계 자체가
  없어진다. 이 규칙은 그 전까지 쓰는 다리다.
