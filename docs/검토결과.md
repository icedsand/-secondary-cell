# 부품 리비전 일괄 생성 rule — 검증 / 디버깅 결과

대상 : `rules/BatchRevisionGeneration.iLogicVb`

문법은 문제가 없었습니다. Sub / Function / Try / For / Do / If 짝이 모두 맞고,
`Finally` 안에서 밖으로 빠져나가는 문장(VB 컴파일 오류)도 없습니다.
`System.IO.Path` 풀네임 사용, `Sub Main` 밖에 선언을 두지 않은 것도 규칙대로입니다.

문제는 전부 **동작** 쪽에 있었습니다. 아래 12건입니다.

---

## 심각 — 데이터가 잘못되거나 작업이 조용히 누락됨

### [B] 새 모델이 저장되지 않아 "이름은 06B, 부품번호는 06A" 인 파일이 남는다

가장 위험했던 부분입니다.

`SaveAs(newIpt, True)` 는 사본을 뜨는 것이므로, 디스크에 기록된 `06B.ipt` 의
부품번호는 **06A** 입니다. 그 뒤 부품번호를 06B 로 고치는 것은 메모리에서만
일어납니다. 그런데 그 문서는

```vb
newModel = ThisApplication.Documents.Open(newIpt, False)   ' False = 화면에 표시 안 함
```

으로 **숨겨진 채** 열립니다. 사용자에게는 "확인 후 직접 저장하세요" 라고
안내하지만, 화면에 없는 문서는 저장할 방법이 없습니다.

결과적으로 인벤터를 닫는 순간 부품번호 수정과 설명(현품수정) 수정이 통째로
날아가고, 파일명만 06B 인 파일이 남습니다. BOM 과 타이틀블록에 이전 번호가
찍히고, 다음에 이 rule 을 다시 돌리면 "이미 존재" 로 걸러져 손댈 수도 없습니다.

**수정** — 새로 만든 파일만 저장합니다(`SAVE_NEW_FILES`). 원본과 조립도는
그대로 둡니다. 새로 만드는 파일을 저장하는 것은 잃을 것이 없는 동작이고,
"확인 후 저장" 이라는 원칙이 지키려던 대상은 원본과 조립도이기 때문입니다.
모델을 먼저 저장하고 도면을 저장해야 도면이 확정된 참조를 보게 되므로
순서도 그렇게 맞췄습니다. 새 모델도 화면에 보이게 열도록 바꿨습니다
(`SHOW_NEW_MODEL`).

`SAVE_NEW_FILES = False` 로 예전 동작으로 되돌릴 수 있고, 그 경우 마지막
보고 창이 "저장하지 않으면 부품번호가 반영되지 않는다" 고 분명히 알립니다.

### [A] 선택 목록을 훑는 도중에 도면을 열어서 일부 부품이 누락된다

```vb
For Each obj As Object In CType(oAct, Inventor.AssemblyDocument).SelectSet
    ...
    Dim opened = OpenDrawingDoc(dwgPath)   ' ← 열거 도중에 문서를 연다
Next
```

`Documents.Open` 은 활성 문서를 바꿉니다. COM 컬렉션을 열거하는 도중에
그 컬렉션이 딸린 문서 상태를 건드리면 열거가 끊기거나 항목을 건너뜁니다.
부품 8개를 골랐는데 3개만 처리되는 식으로, 오류 없이 조용히 빠집니다.

**수정** — `SelectSet` 을 먼저 `List` 로 복사한 뒤, 열거가 끝난 다음에 도면을
엽니다.

### [L] 같은 모델을 보는 도면이 둘 이상 열려 있으면 배치가 통째로 중단된다

조립도에서 첫 부품을 대치하면 인벤터는 더 이상 참조되지 않는 원본 모델
문서를 닫습니다. 그 뒤 다음 항목에서

```vb
Dim oldIpt As String = models(ix).FullFileName
```

이 죽은 COM 개체를 건드려 예외가 납니다. 이 줄은 항목별 `Try` 밖에 있어서
바깥 `Try` 가 잡고, **남은 항목이 전부 처리되지 않은 채** 끝납니다.

**수정** — 모델 기준으로 중복 도면을 걸러내고, 실행에 필요한 경로와
부품번호는 실행을 시작하기 전에 미리 붙잡아 둡니다.

### [C] `ASK_FIELD_MOD = False` 로 두면 (현품수정) 표기가 전부 지워진다

선택창을 건너뛰면 `isFieldMod` 가 전부 `False` 로 남고, `ApplyTag(want:=False)`
가 **기존 태그를 제거**합니다. 설정 하나를 끄면 모든 리비전에서 현품수정
표기가 조용히 사라집니다.

**수정** — 기본값을 "현재 설명의 상태를 그대로 물려받음" 으로 바꿨습니다.
선택창을 띄우든 안 띄우든 손대지 않은 항목은 그대로 유지됩니다.

### [D] 새 부품번호 중복을 걸러내지 않아 앞 파일을 덮어쓴다

편집창에서 두 항목에 같은 번호를 입력해도 아무도 막지 않습니다. 이후
충돌 검사는 `File.Exists` 만 보므로 **아직 만들어지지 않은** 두 번째 항목은
통과하고, 실행 단계에서 첫 번째 결과물을 그대로 덮어씁니다.
파일명에 쓸 수 없는 문자(`/ : * ?` 등)도 걸러지지 않아 `SaveAs` 가 알아보기
힘든 COM 오류로 죽습니다.

**수정** — 편집창에서 확인을 누를 때 빈칸 / 금지문자 / 현재 번호와 동일 /
목록 내 중복 / 기존 파일 충돌을 한꺼번에 검사하고, 고칠 때까지 창을 닫지
않습니다. 기존 파일 충돌도 이제 편집창에서 바로 고칠 수 있어, 전체를
중단시키는 대신 그 자리에서 해결됩니다.

### [E] 다른 조립도의 같은 이름 구성요소까지 대치한다

```vb
If String.Equals(v.Name, sel.Name, StringComparison.Ordinal) Then Return True
```

배치 이름(`Part1:1`)은 **한 조립도 안에서만** 고유합니다. `ReplaceInAssemblies`
는 열려있는 모든 조립도를 훑으므로, 다른 조립도에 있는 동명 배치가 선택된
것으로 판정되어 함께 바뀝니다. "선택한 것만 대치" 를 골랐을 때 엉뚱한
조립도가 수정됩니다.

**수정** — `소속 문서 경로 || 배치 이름` 을 키로 비교합니다.
(COM 개체는 같은 대상이라도 래퍼가 달라 `Is` 비교가 실패할 수 있어서
이름 비교 자체는 필요합니다. 범위만 좁힌 것입니다.)

### [F] 도면 참조를 바꾸면서 그 컬렉션을 열거한다

`ReplaceReference` 는 `ReferencedFileDescriptors` 를 변경합니다. 열거 도중에
부르면 [A] 와 같은 이유로 나머지가 건너뛰어질 수 있습니다.

**수정** — 먼저 `List` 로 복사한 뒤 대체합니다. 덧붙여, 경로 표기가 달라
(매핑 드라이브 ↔ UNC) 매칭에 실패하는 경우를 위해 파일명이 같은 참조를 찾는
2차 시도를 넣었습니다. 예전에는 이 경우 "대상 없음" 이라고만 적고 넘어가서,
새 도면이 옛 모델을 계속 보고 있는 것을 알아채기 어려웠습니다.

## 요청 반영

### [N] 대치 범위 창의 취소를 실제 취소로

`[취소]` 가 "조립도 대치는 하지 않음 (파일만 생성)" 이었습니다. 취소라고
적힌 버튼이 작업을 계속하는 것은 기대와 어긋납니다.

이제 취소는 **규칙 실행 자체를 중단**합니다. 파일도 만들지 않습니다. 이 창은
파일을 만들기 전에 뜨므로 되돌릴 것이 없습니다.

덧붙여, 규칙이 **직접 연 도면은 도로 닫아** 실행 전 상태로 돌립니다. 조립도에서
부품을 선택해 실행하면 규칙이 해당 도면들을 자동으로 여는데, 취소했을 때 그것들이
그대로 열린 채 남으면 "취소했는데 화면이 바뀌어 있는" 상태가 됩니다.
원래 열려있던 도면은 목록에 없으므로 건드리지 않습니다.

같은 처리를 다른 취소 지점에도 넣었습니다 — 도면 선택 창, 현품수정 창,
부품번호 편집 창, 최종 확인 창, 파일 이름 충돌로 중단될 때.

"파일만 생성" 선택지는 **배치를 특정하지 못했을 때 뜨는 창**에만 남겨두었습니다.
그 상황에서는 어느 것을 바꿀지 모르니 "일단 파일만" 이 합리적인 선택지이기
때문입니다. 조립도 대치를 아예 끄려면 `REPLACE_IN_ASM = False` 로 둡니다.

## 보통 — 보고가 틀리거나 사용자가 판단을 잘못하게 됨

### [G] 대치 개수를 실제보다 크게 센다

```vb
occ.Replace(newPath, True)
hit += victims.Count      ' 실패한 것까지 성공으로 계산
Exit For
```

**수정** — 하나씩 `Replace(newPath, False)` 로 바꾸며 성공한 것만 셉니다.
조립도별로 성공 / 실패 개수를 나눠 보고합니다.

### [H] 배치 수를 "가장 많은 조립도 하나" 기준으로만 센다

`CountOccurrences` 가 `If t > total` 로 최대값만 남깁니다. 부품이 여러
조립도(하위 조립도 포함)에 흩어져 있으면 "3개 중 2개 선택" 같은 안내가
틀리고, 사용자가 대치 범위를 잘못 고릅니다.

**수정** — 열려있는 모든 조립도를 합산하고 조립도 이름을 함께 보여줍니다.
하위 조립도의 부품은 그 하위 조립도 문서의 `Occurrences` 에만 있으므로
중복 계산되지 않습니다.

### [I] 목록에서 항목이 이유 없이 사라진다

하이픈 개수 미달, 부품번호 형식 불일치, 리비전 문자 해석 실패, 참조 모델이
1개가 아닌 경우가 전부 설명 없이 `Continue For` 로 빠졌습니다.
특히 `SKIP_LETTERS` 에 넣은 문자가 이미 부품번호에 쓰여 있으면
(`SKIP_LETTERS="IOQSXZ"` 인데 부품번호가 `...-06I`) 조용히 사라집니다.

**수정** — 제외 사유를 모아 보고합니다.

### [J] 실패하면 문서와 파일이 방치된다

2~4단계에서 실패해 `Continue For` 로 빠지면 새로 연 문서는 열린 채 남고,
디스크에는 만들다 만 `06B.ipt` 가 남습니다. 다음 실행에서 이 파일이
"이미 존재" 로 걸려 정상 작업을 막습니다.

**수정** — 실패하면 새로 연 문서를 닫고, 디스크에 남은 파일 목록을 결과
창에 따로 보여줍니다.

### [M] [E] 를 고치다가 "선택한 것만 대치" 질문을 없애 버림 — 회귀

`[E]` 를 고치면서 `occ.Parent.Document.FullFileName` 로 구성요소의 소속
조립도를 알아내 비교했습니다. 그런데 **선택한 개체와 열거한 개체가 이 값을
서로 다르게 내놓으면** 판정이 통째로 실패해 선택된 개수가 0 이 됩니다.

```vb
If total > 1 AndAlso mine > 0 AndAlso mine < total Then   ' mine = 0 → 통과 못 함
```

그러면 질문이 뜨지 않고, `mode` 가 기본값 0(전체 대치)인 채로 넘어갑니다.
사용자 입장에서는 **질문이 사라지고 부품이 전부 바뀌어 버립니다.**

이 판정 방식 자체가 잘못이었습니다. 소속 문서는 구성요소에게 되물을 필요가
없는 값입니다.

- 열거 중인 개체의 소속 = 지금 훑고 있는 조립도 문서
- 선택한 개체의 소속 = 실행 시점의 활성 문서 (선택은 활성 문서에서만 일어남)

둘 다 **호출하는 쪽이 이미 확실히 알고 있는** 값이라, 개체 상태에 따라
흔들리지 않습니다. 이제 이 두 값을 인자로 넘겨 판정합니다.
`[E]` 가 막으려던 것(다른 조립도의 동명 배치까지 대치)은 그대로 막힙니다.

덧붙여 실패 방식도 바꿨습니다. 배치를 특정하지 못하면 이제 조용히 넘어가지
않고 "전부 대치 / 대치 안 함" 을 묻습니다. **되돌릴 수 없는 작업의 기본값은
"묻기" 여야 합니다.**

### [K] 그 밖에

- `ThisApplication.ActiveDocument` 를 `Try` 로 감쌌습니다 (문서가 하나도
  열려있지 않을 때 대비).
- 폼을 `Try / Finally` 로 확실히 `Dispose` 합니다. 예전에는 예외가 나면
  누수됐습니다.
- 도면 경로 목록과 부품 이름 목록을 같은 `seenDwg` 에 섞어 담던 것을
  분리했습니다.
- `ReadPN` 의 `"읽기실패"` 문자열 판정을 없앴습니다. 실제 부품번호가 그
  문자열일 가능성은 없지만, 값으로 오류를 표현하는 방식은 위험합니다.
  이제 `""` 를 돌려주고 `IsNullOrWhiteSpace` 로 판정합니다.
- `DocumentTypeEnum` 을 풀네임으로 적었습니다.
- 태그를 떼면서 생긴 두 칸 공백을 정리합니다.

## 검증한 것

- **구조** : Sub / Function / Try / For / Do / If 짝 일치, `Finally` 밖으로
  분기하는 문장 없음 — 통과.
- **리비전 증가** : `NextRev` / `BumpPartNumber` 를 포팅해 확인.
  `06 → 06A`, `06Z → 06AA`, `06AZ → 06BA`, `06ZZ → 06AAA`,
  `SKIP_LETTERS="IOQSXZ"` 에서 `06H → 06J`, `06Y → 06AA` — 전부 정상.
  소문자 리비전(`06a`), 숫자로 끝나지 않는 번호(`ABC-DEF`), 제외 문자가 이미
  쓰인 번호(`06I`)는 `""` 를 돌려주고 이제 사유와 함께 보고됩니다.
- **설명 태그** : 붙이기 / 떼기, 중복 태그, 중간에 낀 태그, 빈 문자열 —
  전부 의도대로 동작.

## 검증하지 못한 것

인벤터가 없는 환경이라 **COM 호출은 실제로 돌려보지 못했습니다.**
`SaveAs` / `Replace` / `ReplaceReference` / `Save` 의 동작은 API 규약과
원본 코드의 의도를 근거로 판단했습니다.

실제 적용 전에 **복사본 폴더에서 한 번 돌려 보시길** 권합니다. 특히 확인할 것:

1. 새로 만든 `06B.ipt` 의 부품번호가 파일에 저장되어 있는가
2. `06B.idw` 가 `06B.ipt` 를 보고 있는가 (참조 대체 2차 시도가 동작했는지)
3. 조립도 대치 개수가 보고와 일치하는가
4. 하위 조립도에 있는 부품이 의도대로 처리되는가
