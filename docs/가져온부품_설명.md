# 가져온 부품 새 번호로 저장 rule

대상 : `rules/ImportPartsRenumber.iLogicVb`

## 왜 따로 만들었나

다른 유닛 조립도에서 부품을 복사해 붙여넣으면, 그 부품은 여전히 **원래 유닛
폴더의 파일**을 가리킵니다. 리비전 생성 규칙은 새 파일을 원본 옆에 만들기 때문에
이름을 바꿔도 원래 유닛 폴더에 저장됩니다.

리비전 생성 규칙은 잘 쓰고 계시므로 건드리지 않고, 핵심 로직(사본 저장 → 참조
대체 → 타이틀블록 → 저장 → 대치)을 그대로 가져와 별도 규칙으로 만들었습니다.

## 리비전 생성 규칙과 다른 점

| | 리비전 생성 | 가져온 부품 새 번호 |
|---|---|---|
| 저장 폴더 | 원본 부품 폴더 | 지금 조립도의 부품 폴더 |
| 새 이름 | 리비전 문자 +1 | 그 폴더 마지막 번호 +1 |
| 조립도 대치 | 열려있는 모든 조립도 | **지금 조립도만** |
| 대상 | 부품 / 조립품 | 부품만 |

**조립도 대치 범위가 가장 중요한 차이입니다.** 복사해 온 원래 유닛 조립도가
열려 있으면, 리비전 규칙 방식으로는 그쪽 부품까지 새 유닛 번호로 바뀌어 원래
유닛이 망가집니다.

## 저장 폴더를 정하는 방법

조립도가 `GMKS-ST2601-ETR01.iam` 이면, 조립도가 쓰는 부품 중
`GMKS-ST2601-ETR01-` 로 시작하는 것들이 **가장 많이 들어 있는 폴더**를 고릅니다.
그런 부품이 하나도 없으면 조립도 파일이 있는 폴더입니다.

실행하면 이렇게 보여주고, 틀렸으면 다른 폴더를 고를 수 있습니다.

```
가져온 부품을 저장할 폴더와 번호입니다.

   폴더        : D:\Work\GMKS-ST2601\ETR01
   번호 형식   : GMKS-ST2601-ETR01-##
   마지막 번호 : GMKS-ST2601-ETR01-59
   새 번호     : GMKS-ST2601-ETR01-60  ~  GMKS-ST2601-ETR01-62   (3개)

[예]     이 폴더에 이 번호로 저장
[아니오]  다른 폴더 선택
[취소]   규칙 실행 취소
```

폴더가 지금 프로젝트(IPJ) 작업공간 밖이면 경고를 덧붙입니다.

## 번호를 정하는 방법

대상 폴더의 `.ipt / .iam / .idw / .dwg` 이름 중 `이름-숫자` 꼴을 모아 가장 큰
숫자 + 1 을 씁니다.

- **리비전 문자는 무시** — `ETR01-59A` 가 있으면 59로 봅니다 → 다음은 60
- **이름 체계** — 조립도 이름과 같은 것 우선, 없으면 폴더에서 가장 많은 것
- **자릿수** — 기존 번호를 따릅니다 (`59→60`, `099→100`)
- **여러 개** — 원래 부품번호 순으로 정렬해 차례로 붙입니다
- 다른 체계 파일(규격품 등)이나 엑셀 같은 다른 파일은 세지 않습니다
- **새 번호 편집창에서 얼마든지 고칠 수 있습니다** (기존 기능 그대로)

검증 — 번호 로직을 포팅해 실제 파일명으로 확인했습니다.

| 폴더 상황 | 마지막 | 새 번호 |
|---|---|---|
| `-01 ... -58, -59` | `-59` | `-60, -61, -62` |
| `-59, -59A` | `-59A` | `-60` |
| `-099, -100` | `-100` | `-101` |
| 규격품 볼트가 섞임 | `ETR01-13` | `ETR01-14` |
| 조립도 이름 체계 없음 (`ETX-08`) | `ETX-08` | `ETX-09` |
| 빈 폴더 | 없음 | `-01` |

## 건너뛰는 것

- **이미 대상 폴더에 있는 부품** — 창 선택으로 이 유닛 부품이 섞여 들어와도
  번호가 바뀌지 않게 (`SKIP_LOCAL_PARTS`)
- **하위 조립품** — 사본을 만들어도 구성 부품은 원래 폴더에 남으므로
- **도면이 없는 부품** — 같은 폴더에 같은 이름의 `.idw / .dwg` 가 필요합니다
- **하이픈이 2개 미만인 부품번호** — 규격품 보호

건너뛴 항목은 최종 확인 창에 사유와 함께 나옵니다.

## Inventor 2026 대비

이번에 겪은 문제를 미리 피했습니다.

- **정규식(Regex)을 쓰지 않습니다.** 최신 .NET 에서 별도 어셈블리라 iLogic 참조
  목록에 없을 수 있습니다. 번호는 손으로 잘라 읽습니다.
- **`Using` 문을 쓰지 않습니다.** `IDisposable` 로의 인터페이스 변환이라
  `AcceptButton` 과 같은 오류가 날 수 있습니다.
- Enter / Esc 버튼은 리플렉션으로 지정합니다.

## 확인이 필요한 것

- **다른 iProperty** — 부품번호와 설명(현품수정)만 바꿉니다. 프로젝트명이나
  유닛명 같은 다른 속성이 원래 유닛 값으로 남아 있을 수 있습니다.
- **하위 조립품 안의 부품** — 대치는 조립도 최상위만 봅니다. 하위 조립품 안의
  부품을 고르면 파일은 만들어지지만 대치되지 않고, 계획 창에 그렇게 표시됩니다.
- COM 호출은 인벤터 없이 작성했습니다. 복사본 폴더에서 먼저 시험해 주세요.
