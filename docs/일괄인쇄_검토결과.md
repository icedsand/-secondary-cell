# 도면 일괄 인쇄 rule — Inventor 2026 이관 및 검토

대상 : `rules/BatchPrint.iLogicVb`

## 컴파일 오류 (수정함)

원인은 하나입니다. **iLogic 컴파일 대상이 .NET Framework 4.x 에서 최신 .NET 으로
바뀌었습니다.** 오류에 나오는 `System.Private.Windows.Core, Version=10.0.0.0` 이
그 증거입니다. 규칙 코드는 그대로인데 컴파일러가 딛고 선 바닥이 바뀐 것입니다.

### [P] 514 / 529행 — 레지스트리로 프린터 목록 읽기

.NET Framework 에서는 `Microsoft.Win32.Registry` 가 `mscorlib` 안에 있어 늘 쓸 수
있었습니다. 최신 .NET 에서는 별도 어셈블리로 분리되었고 iLogic 이 참조하지
않습니다.

**수정** — 레지스트리를 아예 걷어내고 .NET 의 정식 창구인
`PrinterSettings.InstalledPrinters` 를 씁니다. 레지스트리보다 정확합니다. 예전
방식은 `Devices` 키를 훑는 것이라 프린터가 아닌 항목까지 목록에 넣고, 일부
네트워크 프린터는 빠뜨렸습니다.

타입을 직접 적지 않고 이름으로 찾습니다. `System.Drawing` 이 iLogic 참조 목록에
없으면 직접 적었을 때 **또 컴파일이 깨지고, 컴파일 오류는 Try 로 막을 수
없기** 때문입니다. 이름으로 찾으면 컴파일은 무조건 통과하고, 실패해도 빈 목록이
될 뿐입니다. 빈 목록이면 규칙이 이미 프린터 이름을 직접 입력받게 되어 있습니다.

참조가 문제없는 것이 확인되면 주석에 적어둔 한 줄로 줄일 수 있습니다.

### [O] 699 / 700행 — Enter / Esc 기본 버튼 지정

```vb
frm.AcceptButton = btnOK
frm.CancelButton = btnCancel
```

`Button` 을 `IButtonControl` 로 바꾸는 **인터페이스 변환**입니다. 컴파일러는
변환이 되는지 보려고 `Button` 이 구현한 인터페이스를 전부 훑는데, 새 WinForms
에서는 그 목록에 참조되지 않은 `System.Private.Windows.Core` 의 타입
(`IHandle(Of )`, `IPersist.Interface`) 이 들어 있습니다.

`Text` / `Width` / `DialogResult` 같은 값 대입은 인터페이스 변환이 아니라
멀쩡했습니다. 그래서 딱 이 두 줄만 오류가 났습니다.

**수정** — 리플렉션으로 넘깁니다(`SetDefaultButtons`). 리비전 규칙과 같은 처리를
했습니다.

## 함께 고친 것

- **매수 파싱** — `CInt(CStr(sel3).Replace(" 매",""))` 가 예상 밖의 값을 만나면
  규칙이 그 자리에서 죽었습니다. 감싸고 1~99 로 제한합니다.
- **폼 누수** — `frm.Dispose()` 가 `Finally` 밖에 있어 예외가 나면 누수됐습니다.

## 검증한 것

- **구조** : Sub / Function / Try / For / Do / Select / If 짝 일치 — 통과.
- **이전판 계산** : `PrevPartNumber` 를 포팅해 확인.
  `06B→06A`, `06A→06`, `06AA→06Z`, `06BA→06AZ`, `06AAA→06ZZ`,
  리비전 없는 `06` 은 `""`(이전판 없음). 리비전 생성 규칙의 `BumpPartNumber` 와
  정확히 역함수입니다.
- COM 호출은 인벤터가 없는 환경이라 실제로 돌려보지 못했습니다.

## 실행 후 나온 문제 (수정함)

### [Q] 이전판(구본) 도면이 안 열려있을 때 인쇄가 안 됨

**증상** — 이미 열려있던 이전판은 멀쩡히 인쇄되는데, 규칙이 직접 연 이전판만
아무것도 안 나옴. 오류도 안 뜸.

그 둘의 차이는 딱 두 가지였고, 둘 다 원인이 될 수 있습니다.

**1. 숨겨서 열었습니다**

```vb
ThisApplication.Documents.Open(dwgPath, False)   ' False = 화면에 표시 안 함
```

화면에 그려진 적이 없는 도면은 `SubmitPrint` 를 해도 인쇄할 내용이 준비되지
않아 아무것도 안 나오는 경우가 있습니다. 이미 열려있던 도면은 당연히 화면에
있으니 멀쩡했습니다.

→ 보이게 엽니다 (`OPEN_PREV_VISIBLE`).

**2. 인쇄 직후 바로 닫았습니다**

`SubmitPrint` 는 작업을 넘기고 **곧바로 돌아옵니다.** 인쇄 데이터가 스풀러로 다
넘어가기 전에 문서를 닫으면 그 작업이 통째로 사라집니다. 규칙이 연 도면만
`CLOSE_OPENED` 로 닫으므로, 이미 열려있던 도면은 이 문제를 겪지 않았습니다.

→ 잠시 기다린 뒤 닫습니다 (`CLOSE_DELAY_SEC`, 기본 5초). 기다리는 동안 인벤터가
얼어붙어 보이지 않도록 짧게 끊어 자면서 메시지를 처리합니다.

앞선 검토에서 3번으로 적어둔 항목이 실제로 터진 것입니다.

**그래도 안 되면** — `CLOSE_OPENED = False` 로 두고 시험해 보세요.
그때 인쇄가 되면 원인은 2번이므로 `CLOSE_DELAY_SEC` 를 늘리면 됩니다.
`False` 로 둬도 안 되면 1번 쪽이니 알려주세요.

## 확인이 필요한 것 (고치지 않음)

### 1. 이전판 도면을 같은 폴더에서만 찾습니다

`FindDrawingByName` 은 현재 도면과 **같은 폴더**만 봅니다.

작업폴더가 옮겨간 상황이라 특히 확인이 필요합니다. 이전 리비전 도면이 다른
폴더(보관용 등)에 있으면 못 찾고 "도면 파일을 찾지 못함" 으로 빠집니다.
찾을 폴더를 늘려야 한다면 알려주세요.

### 2. SKIP_LETTERS 와 어긋날 수 있습니다

리비전 생성 규칙에는 `SKIP_LETTERS`(리비전에서 제외할 알파벳)가 있는데, 이
규칙의 `PrevPartNumber` 는 항상 A~Z 전체를 씁니다.

지금은 `SKIP_LETTERS = ""` 라 일치하지만, 나중에 `"IOQSXZ"` 같은 값을 넣으면
**이전판 번호를 틀리게 계산합니다.** 예를 들어 `06J` 의 이전판은 `06H` 인데
`06I` 로 계산합니다. 제외 문자를 쓰기로 하시면 두 규칙을 함께 고쳐야 합니다.

### 3. 인쇄 직후 문서를 닫습니다 → [Q] 에서 수정함

실제로 이 문제가 터졌습니다. 위 [Q] 항목을 보세요.

### 4. 같은 모델을 참조하는 도면이 둘일 때

두 도면이 같은 모델을 참조하면 부품번호가 같아 이전판도 같아지고, 그 이전판이
두 번 인쇄됩니다. 드문 경우라 손대지 않았습니다.
