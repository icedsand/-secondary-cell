# Pack and Go 폴더 정리 rule

대상 : `rules/PackAndGoReorganize.iLogicVb`

Pack and Go 로 꺼낸 프로젝트를 유닛별 폴더 규칙에 맞춰 **새 위치에 다시 짜 넣는**
규칙입니다. 라이브러리를 보고 있던 구매품은 그것을 쓰는 유닛 / 하부 유닛의 구매품
폴더로 복사하고, 모든 참조를 새 위치로 다시 연결합니다.

- 파일 이름은 하나도 바꾸지 않습니다.
- 원본 폴더와 라이브러리는 읽기만 합니다.

## 설정 (규칙 맨 위)

| 항목 | 값 |
|---|---|
| `SRC_ROOT` | `O:\새 폴더\Workspaces\작업공간\B5. 개발설계TF 폴더 (아산)\01. GM SAMPLE STACKING 검토` |
| `LIB_ROOT` | `O:\새 폴더\Workspaces\작업공간\04. Library` |
| `DST_BASE` | `O:\스태킹 PAG` → 결과는 `O:\스태킹 PAG\01. GM SAMPLE STACKING 검토\` |
| `ASIS_FOLDERS` | `99. 자재` (원래 구조 그대로 옮김) |
| `COMMON_LIB_DIRS` | `Z. BOLT|Z. NUT|Z. WASHER` |
| `COMMON_KEYWORDS` | `와셔|WASHER` |
| `SKIP_DIRS` | `_V|OldVersions` |

## 결과 구조

```
O:\스태킹 PAG\01. GM SAMPLE STACKING 검토\
 ├─ 01. GM SAMPLE STACKING 검토.ipj
 ├─ 00. 전체 조립도\                 GM Sample Stacking ASSY (구미조립도).iam
 ├─ 99. 자재\                        원래 구조 그대로
 ├─ _정리로그\                       미리보기 / 복사 / 재연결 기록
 └─ 05. STACK STAGE\
     ├─ 05. STACK STAGE.ipj
     ├─ 01. 조립도\                  GMKS-ST2601-SST00(구조변경신규).iam
     ├─ 02. 하부조립도\
     │   └─ 03. Stack Stage\
     │       ├─ 03. Stack Stage.ipj
     │       ├─ 01. 조립도\          SST03A.iam + 그 안의 하위 iam (iam 없으면 폴더 없음)
     │       ├─ 02. 부품도\          SST03-xx.ipt / .idw / 미러 ipt
     │       └─ 03. 구매품\          품번 폴더째 (_V 제외)
     │           └─ 공용부품\        볼트 / 너트 / 와셔
     ├─ 03. 부품도\                  SST00-xx 가공품
     ├─ 04. 구매품\                  유닛 조립도에 바로 들어간 구매품
     └─ 99. 미분류\                  도번 없고 어디에도 안 쓰인 파일 (원래 하위 경로 유지)
```

하부 유닛이 없는 유닛은 하부조립도 폴더 없이 `01. 조립도 / 02. 부품도 / 03. 구매품` 입니다.

```
08. Pulling Transfer\                PUT01 하나뿐 → 하부조립도 없음
 ├─ 08. Pulling Transfer.ipj
 ├─ 01. 조립도\                       PUT01.iam (+ PUT01-10.iam 같은 하위 iam)
 ├─ 02. 부품도\                       PUT01-xx.ipt / .idw
 └─ 03. 구매품\
```

## 분류 규칙

### 가공품 / 조립도 - 도번으로

`GMKS-ST2601-SST03-10A` → 유닛 기호 `SST`, 하부 유닛 `03`

| 도번 | 위치 |
|---|---|
| `SST00…iam` | 유닛 `01. 조립도` |
| `SST00-xx` | 유닛 `03. 부품도` |
| `SST03A.iam`, `SST03-10.iam` | 하부 유닛 03 `01. 조립도` |
| `SST03-xx.ipt` | 하부 유닛 03 `02. 부품도` |

하부 유닛이 무엇인지는 아래 "유닛 레벨과 하부 유닛" 을 보세요.

- 유닛 기호는 유닛 폴더 안 파일 이름에서 정합니다. `SST00` 처럼 00 번 iam 이
  있으면 그것을, 없으면 가장 많이 나오는 기호를 씁니다.
- **도번이 없거나 다른 유닛 기호**인 파일은 그 파일을 쓰는 조립도와 같은 곳으로
  보냅니다. 미리보기 CSV 의 비고에 표시됩니다.
- 어디에도 안 쓰인 파일은
  - 도번이 없으면 → `99. 미분류`
  - 다른 유닛 기호면 → **가져가지 않음** (CSV 에 "제외")

### 유닛 레벨과 하부 유닛

**열려 있는 조립도에서 유닛 조립도를 찾아** 그 번호를 유닛 레벨로 정합니다.
유닛 조립도는 전체 조립도 바로 아래에 들어간 그 유닛의 iam 입니다
(유닛 조립도에서 실행했으면 그 조립도).

| 유닛 | 유닛 조립도 | 유닛 레벨 | 하부 유닛 |
|---|---|---|---|
| STACK STAGE | `SST00(구조변경신규).iam` | 00 | 01 ~ 06 → `02. 하부조립도` |
| Pulling Transfer | `PUT01.iam` | 01 | 없음 → 하부조립도 없이 유닛에 바로 |

- 원본에 00 번 파일이 있으면 언제나 00 이 유닛 레벨입니다. 시험하다가 하부 조립도
  (`SST03A`)를 열고 실행해도 03 이 유닛이 되지 않습니다.
- 미리보기 요약 창의 "유닛 기호" 줄에 유닛마다 어느 조립도로 정했는지 나옵니다.

### 하부 유닛 폴더 이름

**원래 저장되어 있던 폴더 이름을 그대로** 씁니다.

1. 그 번호(SST03) 파일들이 실제로 들어 있던 폴더 → `03. Stack Stage`
   (이미 정리돼 있던 유닛은 `02. 하부조립도\01. X축` 처럼 한 단계 안쪽도 봅니다)
2. 없으면 번호가 같은 기존 폴더
3. 그것도 없으면(파일이 전부 `00. 조립도` 에 있음) 임시 이름 `07. SST07`
   → 미리보기 요약 창에 따로 표시. 직접 이름을 바꾸시면 됩니다.

`00. 조립도`, `부품도`, `구매품` 같은 분류 폴더는 하부 유닛 폴더로 보지 않습니다.
번호 없는 폴더(`Gripper`)에 들어 있었으면 `09. Gripper` 처럼 번호를 붙입니다.

### 구매품

라이브러리(`04. Library`) 또는 원본의 `…구매품` 폴더에 있는 파일입니다.

| 원래 위치 | 복사되는 모양 |
|---|---|
| `Library\[제작사]\[종류]\[품번 폴더]\…` | `구매품\[품번 폴더]\…` (폴더째) |
| `Library\[제작사]\[종류]\파일` (예외 깊이 포함) | `구매품\파일` |
| `Library\Z. BOLT\…`, `Z. NUT`, 이름에 와셔 | `구매품\공용부품\파일` |
| 원본 `03. 구매품\AR10…\…` (이미 정리돼 있던 유닛) | `구매품\AR10…\…` |

- 구매품은 **그것을 쓰는 조립도가 있는 곳**의 구매품 폴더로 갑니다.
  하부 유닛 iam 없이 유닛 조립도에 바로 들어간 구매품은 유닛의 구매품 폴더로 갑니다.
- 파일만 있는 구매품(`6800.ipt`)은 옆에 같은 이름 도면(`6800.idw`)이 있으면 같이 갑니다.
- 같은 구매품을 하부 유닛 여러 곳에서 쓰면 **하부 유닛마다 복사**합니다.
- 같은 하부 유닛 안에서 여러 번 쓰면 하나만 둡니다.

### 도면

같은 이름의 모델(ipt / iam)과 같은 폴더로 갑니다.

## 사용법

### 1) 미리보기 - 아무것도 복사하지 않음

1. 원본 프로젝트(작업공간)로 **원본 조립도**를 엽니다.
   - 시험 : 작은 유닛 조립도 (예: `05. STACK STAGE\00. 조립도\…SST00….iam`)
   - 실제 : 전체 조립도 `GM Sample Stacking ASSY (구미조립도).iam`
2. 규칙 실행 → `1. 미리보기`
3. `_정리로그\미리보기_날짜.csv` 를 엑셀로 열어 확인합니다.
   - **비고**가 있는 줄 : 도번 없음, 다른 유닛 도번, 원본 폴더 밖, 이름 겹침,
     전체 조립도에 바로 들어간 부품(유닛 밖 → `00. 전체 조립도` 안. 요약 창에도 개수 표시)
   - **제외** : 가져가지 않는 파일
   - **참조 끊김** : 원본에서 이미 못 찾는 링크

### 2) 복사

1. 같은 조립도에서 규칙 실행 → `2. 복사`
2. 파일 복사 + 프로젝트 파일 생성
   - 맨 위 ipj 는 인벤터로 만들고, 유닛 / 하부 유닛 ipj 는 그것을 복사합니다
     (작업공간이 `.` 이라 각자 자기 폴더가 작업공간이 됩니다).
   - 완료 창에 표시되는 **작업공간 경로를 확인**하세요.
3. 이 단계가 끝나도 복사본의 참조는 아직 원본을 보고 있습니다.

### 3) 재연결

1. 인벤터에서 **모든 파일 닫기**
2. 프로젝트 창에서 `01. GM SAMPLE STACKING 검토.ipj` 활성화
3. **새 부품(빈 ipt)** 하나 열기 - 저장하지 않아도 됩니다
4. 규칙 실행 → `3. 재연결`
5. 끝나면 새 위치의 전체 조립도를 열어 링크가 모두 잡히는지 확인합니다.
   `_정리로그\재연결_날짜.csv` 에 "못 찾음 / 대체 실패" 가 있으면 알려주세요.

재연결은 새 프로젝트에서 복사본을 하나씩 열고(끊긴 참조는 건너뛰고 열기),
끊긴 참조마다 새 위치의 복사본으로 `ReplaceReference` 한 뒤 저장합니다.
부품 → 조립도(아래부터) → 도면 순서입니다.

## 다시 돌릴 때

- 결과 위치에 이미 있는 파일은 덮어쓰지 않고 건너뜁니다. 중간에 멈췄으면
  그대로 다시 실행하면 이어서 됩니다.
- 처음부터 다시 하려면 결과 폴더를 지우고 실행하세요.
- 유닛으로 시험한 뒤 전체로 돌릴 때도 결과 폴더를 지우고 시작하는 것이 깔끔합니다.

## 알아둘 것

- 다른 유닛에 같은 구매품(예: `6204ZZ.ipt`)이 이름 그대로 각각 들어가므로,
  전체 조립도 하나에 같은 이름의 파일이 서로 다른 폴더에서 들어옵니다.
  인벤터는 전체 경로로 구분하므로 문제없지만, Vault 에 체크인하면 파일명 중복
  정책에 걸릴 수 있습니다.
- `.ipj`, `_V`, `OldVersions`, 잠금 파일(`~$…`, `.lck`)은 가져가지 않습니다.
