# Pack and Go 폴더 정리 rule

대상 : `rules/PackAndGoReorganize.iLogicVb`

Pack and Go 로 꺼낸 프로젝트를 유닛별 폴더 틀에 맞춰 **새 위치에 다시 짜 넣는**
규칙입니다. 목적은 **구매품을 각 유닛 / 하부 유닛에 배치하는 것**입니다.

- 구매품 : 그것을 쓰는 유닛 / 하부 유닛의 구매품 폴더로 복사
- 조립도 / 가공품 : 원래 폴더의 내용물을 **그대로** 새 틀로 옮김 (도번으로 옮기지 않음)
- 모든 참조를 새 위치로 다시 연결

- 파일 이름은 하나도 바꾸지 않습니다.
- 원본 폴더와 라이브러리는 읽기만 합니다.

## 설정 (규칙 맨 위)

| 항목 | 값 |
|---|---|
| `SRC_ROOT` | `O:\JASTECH1\JASTECH1\B5. 개발설계TF 폴더 (아산)\01. GM SAMPLE STACKING 검토` (Vault 작업 폴더) |
| `LIB_ROOT` | `O:\JASTECH1\JASTECH1\04. Library` (없으면 규칙이 멈추고 알려줌) |
| `DST_BASE` | `O:\스태킹 PAG` → 결과는 `O:\스태킹 PAG\01. GM SAMPLE STACKING 검토\` |
| `ASIS_FOLDERS` | `99. 자재` (원래 구조 그대로 옮김) |
| `COMMON_LIB_DIRS` | `Z. BOLT|Z. NUT|Z. WASHER` |
| `COMMON_KEYWORDS` | `와셔|WASHER` |
| `PURCH_DIR_KEYS` | `구매품|표준품` (원본에서 구매품 폴더로 볼 이름. `임시구매품` 포함) |
| `SKIP_DIRS` | `_V|OldVersions` |

### 원본은 Vault 작업 폴더

Pack and Go 는 **조립도가 참조하는 파일만** 모아 오기 때문에, 조립도에서 빠져 있고
폴더에만 있던 파일은 Pack and Go 폴더에 없습니다. 그래서 원본을 Vault 작업 폴더로
잡습니다. (Pack and Go 폴더로 돌리던 경로는 규칙 안에 주석으로 남겨 두었습니다.)

- Vault 파일이 읽기 전용이어도 됩니다. 원본은 **읽기만** 하고, 복사본은 읽기 전용을 풉니다.
  체크아웃도 하지 않습니다.
- 저장은 결과 폴더 안 파일에만 합니다. 재연결 단계에도 "결과 폴더 밖 파일은 열지도
  저장하지도 않는다" 는 확인이 들어 있습니다.
- 규칙은 **내 PC 에 내려받아져 있는 파일만** 볼 수 있습니다. 돌리기 전에 Vault Explorer 에서
  `01. GM SAMPLE STACKING 검토` 폴더와 `04. Library` 폴더를 오른쪽 클릭 →
  **최신 버전 가져오기(Get Latest Version)** 로 하위 폴더까지 받아 두세요.

## 옮기는 규칙

### 원본 폴더 → 새 폴더

원본 폴더 **이름**으로 새 틀에 대응시킵니다. 그 안쪽은 손대지 않습니다.

| 원본 폴더 이름에 들어 있는 말 | 새 폴더 |
|---|---|
| `조립도` (`00. 조립도`, `01. 조립도`) | `01. 조립도` |
| `부품도`, `가공품` | `02. 부품도` (하부 유닛이 있는 유닛 레벨은 `03. 부품도`) |
| `구매품`, `임시구매품`, `표준품` | 구매품 (아래 "구매품") |
| `하부조립도` 안의 폴더 | `02. 하부조립도\그 폴더` (이미 정리돼 있던 유닛) |
| 번호가 붙은 그 밖의 폴더 (`03. Stack Stage`) | `02. 하부조립도\03. Stack Stage` (이름 그대로) |
| 그 밖의 폴더 (`(참고)` 등) | 원래 구조 그대로 (CSV 비고에 표시) |

- 하부 유닛 폴더가 하나도 없는 유닛(Pulling Transfer)은 하부조립도 폴더를 만들지 않습니다.
- 분류 폴더 없이 바로 들어 있는 파일은 iam 은 `01. 조립도`, 나머지는 `02. 부품도` 로 갑니다.
- 조립에 안 쓰이는 파일도 원래 자리 그대로 전부 가져갑니다.

### Stacking 폴더 밖을 가리키는 가공품 / 도면

원본 폴더(`01. GM SAMPLE STACKING 검토`) 밖의 다른 폴더를 가리키는 가공품과 하위 조립도는
**그것을 조립한 조립도가 들어가는 폴더**에 같이 넣습니다. 같은 이름 도면도 같이 갑니다.

```
원본 02. Magazine\02. 가공품\노칭용 매거진\MAGAZINE_H-PJT_양극.iam
      └ 쓰는 부품 : A8. 2차전지\...\MAG-PLATE.ipt (+ .idw), MAG-GUIDE-ASSY.iam 과 그 안 부품
결과  02. Magazine\02. 부품도\노칭용 매거진\
        MAGAZINE_H-PJT_양극.iam, MAG-PLATE.ipt / .idw, MAG-GUIDE-ASSY.iam, MAG-PIN.ipt / .idw
```

- 그 바깥 부품들이 쓰는 구매품은 다른 구매품처럼 그 하부 유닛의 구매품 폴더로 갑니다.
- CSV 비고에 "원본 폴더 밖 파일 - 이것을 조립한 ○○.iam 와 같은 폴더로" 가 나옵니다.
- 여러 조립도가 같이 쓰면 처음 찾은 조립도의 폴더로 갑니다.

### 유닛 조립도 폴더에 섞인 하부 유닛 조립도

유닛 `01. 조립도` 에는 유닛 조립도만 둡니다. 원본 유닛 조립도 폴더에 하부 유닛
조립도(예: `SST03A.iam` 과 그 도면)가 섞여 있으면 **그 번호의 하부 유닛 조립도 폴더**로
보냅니다. 그 번호 폴더가 원본에 없으면 임시 이름(`07. SST07`)으로 만들고 미리보기
요약 창에 "직접 이름을 바꾸세요" 로 표시합니다.

유닛 레벨 번호는 열려 있는 조립도에서 유닛 조립도를 찾아 정합니다
(`SST00(구조변경신규).iam` → 00, `PUT01.iam` → 01). 원본에 00 번 파일이 있으면 언제나 00 입니다.

### 구매품

라이브러리(`04. Library`) 또는 원본의 구매품 / 임시구매품 / 표준품 폴더에 있는 파일입니다.

| 원래 위치 | 복사되는 모양 |
|---|---|
| `Library\[제작사]\[종류]\[품번 폴더]\…` | `구매품\[품번 폴더]\…` (폴더째) |
| `Library\[제작사]\[종류]\파일` (예외 깊이 포함) | `구매품\파일` (옆의 같은 이름 도면 포함) |
| `Library\Z. BOLT\…`, `Z. NUT`, 이름에 와셔 | `구매품\공용부품\파일` |
| 원본 `03. 임시구매품\SMC-ABC\…`, `03. 표준품\…` | `구매품\SMC-ABC\…` |

- 구매품은 **그것을 쓰는 조립도가 원래 있던 유닛 / 하부 유닛**의 구매품 폴더로 갑니다.
- 같은 구매품을 하부 유닛 여러 곳에서 쓰면 **하부 유닛마다 복사**합니다.
- 아무도 안 쓰는 구매품은 그 구매품 폴더가 있던 유닛 / 하부 유닛의 구매품 폴더로 갑니다.

## 사용법

### 1) 미리보기 - 아무것도 복사하지 않음

1. Vault 프로젝트를 활성화하고 Vault 작업 폴더의 **원본 조립도**를 엽니다.
   - 시험 : 작은 유닛 조립도 (예: `05. STACK STAGE\00. 조립도\…SST00….iam`)
   - 실제 : 전체 조립도 `GM Sample Stacking ASSY (구미조립도).iam`
2. 규칙 실행 → `1. 미리보기`
3. `_정리로그\미리보기_날짜.csv` 를 엑셀로 열어 확인합니다.
   - **비고**가 있는 줄 : 분류 폴더가 아니라 원래 구조 그대로 간 것, 하부 유닛 폴더로
     옮긴 하부 유닛 조립도, 원본 폴더 밖 파일, 이름 겹침, 전체 조립도에 바로 들어간 부품
   - **참조 끊김** : 원본에서 이미 못 찾는 링크
4. 요약 창의 "유닛 구성" 에서 유닛마다 하부 유닛 목록 / 하부조립도 없음을 확인합니다.

### 2) 복사

1. 같은 조립도에서 규칙 실행 → `2. 복사`
2. 파일 복사 + 프로젝트 파일 생성
   - 맨 위 ipj 는 인벤터로 만들고, 유닛 / 하부 유닛 ipj 는 그것을 복사합니다
     (작업공간이 `.` 이라 각자 자기 폴더가 작업공간이 됩니다).
   - 완료 창에 표시되는 **작업공간 경로를 확인**하세요.
3. 이 단계가 끝나도 복사본의 참조는 아직 원본을 보고 있습니다.

### 3) 재연결

1. 인벤터에서 **모든 파일 닫기**
2. 프로젝트 창에서 `01. GM SAMPLE STACKING 검토.ipj` 활성화
3. **새 부품(빈 ipt)** 하나 열기 - 저장하지 않아도 됩니다
4. 규칙 실행 → `3. 재연결`
5. 끝나면 새 위치의 전체 조립도를 열어 링크가 모두 잡히는지 확인합니다.
   `_정리로그\재연결_날짜.csv` 에 "못 찾음 / 대체 실패" 가 있으면 알려주세요.

재연결은 새 프로젝트에서 복사본을 하나씩 열고(끊긴 참조는 건너뛰고 열기),
끊긴 참조마다 새 위치의 복사본으로 `ReplaceReference` 한 뒤 저장합니다.
부품 → 조립도(아래부터) → 도면 순서입니다.

## 다시 돌릴 때

- 결과 위치에 이미 있는 파일은 덮어쓰지 않고 건너뜁니다. 중간에 멈췄으면
  그대로 다시 실행하면 이어서 됩니다.
- 처음부터 다시 하려면 결과 폴더를 지우고 실행하세요.
- 유닛으로 시험한 뒤 전체로 돌릴 때도 결과 폴더를 지우고 시작하는 것이 깔끔합니다.

## 알아둘 것

- 다른 유닛에 같은 구매품(예: `6204ZZ.ipt`)이 이름 그대로 각각 들어가므로,
  전체 조립도 하나에 같은 이름의 파일이 서로 다른 폴더에서 들어옵니다.
  인벤터는 전체 경로로 구분하므로 문제없지만, Vault 에 체크인하면 파일명 중복
  정책에 걸릴 수 있습니다.
- `.ipj`, `_V`, `OldVersions`, 잠금 파일(`~$…`, `.lck`)은 가져가지 않습니다.
